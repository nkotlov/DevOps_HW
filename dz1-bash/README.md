# ДЗ 1. Bash script

## Цель задания

Необходимо написать bash-скрипт, который автоматизирует настройку группы `dev`, прав `sudo`, рабочих директорий пользователей, ACL-доступа и логирования.

По условию скрипт должен:

- создать группу `dev`;
- добавить в группу `dev` всех несистемных пользователей;
- выдать группе `dev` права на `sudo` без запроса пароля;
- создать для каждого пользователя директорию по маске `<user_name>_workdir`;
- принимать путь до директорий через ключ `-d`;
- если ключ `-d` не указан, запрашивать путь при запуске;
- создавать директории с правами `660`;
- назначать владельцем директории пользователя;
- назначать группой директории основную группу пользователя;
- добавить группе `dev` доступ на чтение для созданных директорий;
- писать лог одновременно в терминал и в файл.

На скриншоте видно, что правило создано и успешно прошло проверку через `visudo`.

## Как работает скрипт

Скрипт сначала проверяет, что он запущен с правами `root`, потому что создание групп, изменение пользователей, настройка `sudoers` и изменение прав в системных директориях требуют административных прав.

Далее скрипт получает путь для создания рабочих директорий. Если путь передан через ключ `-d`, используется переданное значение. Если ключ не передан, скрипт запрашивает путь у пользователя во время запуска.

После этого создаётся группа `dev`. Если группа уже существует, скрипт не завершается с ошибкой и продолжает выполнение.

Затем создаётся файл `/etc/sudoers.d/dev-nopasswd`, в который записывается правило для выполнения `sudo` без пароля пользователями группы `dev`. После записи файл проверяется командой `visudo -cf`.

Несистемные пользователи определяются по UID. В Linux обычные пользователи обычно имеют UID от `1000`. Для каждого найденного пользователя скрипт добавляет его в группу `dev`, создаёт директорию `<user_name>_workdir`, назначает владельца и группу, выставляет права `660` и добавляет группе `dev` право чтения через ACL.

Логирование реализовано через `tee`, поэтому вывод одновременно отображается в терминале и сохраняется в файл `setup_dev_users.log`.
