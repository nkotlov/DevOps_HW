\# ДЗ 1. Bash script



\## Задание



Необходимо написать bash-скрипт, который:



\- создаёт группу `dev`;

\- добавляет в группу `dev` всех несистемных пользователей;

\- выдаёт группе `dev` права на выполнение `sudo`-команд без запроса пароля;

\- для всех пользователей создаёт директории по маске `<user\_name>\_workdir`;

\- путь до создаваемых директорий должен задаваться через ключ `-d`;

\- если ключ `-d` не задан, путь должен быть запрошен при запуске скрипта;

\- создаваемые директории должны быть с правами `660`;

\- владельцем директории должен быть пользователь;

\- группой директории должна быть основная группа пользователя;

\- для всех созданных директорий группе `dev` должен быть выдан доступ на чтение;

\- весь лог должен писаться одновременно в `stdout` и в файл.



\## Файлы проекта

\- `setup\_dev\_users.log` — лог выполнения скрипта;

\## Пояснение работы скрипта



Скрипт сначала проверяет, что он запущен с правами `root`, так как создание групп, изменение пользователей, настройка `sudoers` и изменение прав в системных директориях требуют административных прав.



Далее скрипт получает путь для создания рабочих директорий. Если путь передан через ключ `-d`, используется переданное значение. Если ключ `-d` не указан, скрипт запрашивает путь вручную при запуске.



После этого создаётся группа `dev`. Если такая группа уже существует, скрипт не завершается с ошибкой, а продолжает выполнение.



Для выдачи `sudo` без запроса пароля создаётся файл:



```bash

/etc/sudoers.d/dev-nopasswd

```



В него записывается правило:



```bash

%dev ALL=(ALL) NOPASSWD:ALL

```



После записи файл проверяется командой:



```bash

visudo -cf /etc/sudoers.d/dev-nopasswd

```



Это нужно, чтобы убедиться, что правило `sudoers` записано корректно.



Несистемные пользователи определяются по UID. В Linux обычные пользователи обычно имеют UID от `1000`. Для каждого найденного пользователя скрипт выполняет следующие действия:



\- добавляет пользователя в группу `dev`;

\- создаёт директорию вида `<user\_name>\_workdir`;

\- назначает владельцем директории этого пользователя;

\- назначает группой директории основную группу пользователя;

\- устанавливает права `660`;

\- добавляет группе `dev` право чтения через ACL.



Права `660` были выставлены по условию задания. Дополнительное право чтения для группы `dev` было добавлено через команду `setfacl`.



Для логирования используется перенаправление вывода через `tee`, поэтому результат выполнения одновременно отображается в терминале и записывается в файл `setup\_dev\_users.log`.
